# Intent: A change of the stack's Keycloak doesn't say that an application's generated admin client moves with it

- Author: Jérôme Wacongne (product owner, tech lead)

- Spec needed: no
- Status: accepted
- Opened: 2026-10-29
- Decided: 2026-10-29
- Supersedes: —
- Mode: bootstrap

## Problem

README, "Keycloak in an application's tests": a change of the stack's Keycloak "shows in the description (an application's check of its pin fails), and the changelog below says what it asks of an application" (`README.md:512-514`). It says nothing of an application's Keycloak admin client.

An application generated by the skills generates that client from the OpenAPI description of Keycloak's admin API, for one Keycloak version (the skills' intent 0111, approved 2026-10-29: the build fetches `org.keycloak:keycloak-api-docs-dist:<version>` by the application's pin). A version change of the stack's Keycloak changes that client: fields (26.8's `organizationLinks`, where an identity provider's `organizationId` reads back `null`) and method signatures (from 26.7.2 to 26.8.1, the organizations list, their count and the invitation gain a parameter, which shifts the positional arguments). Tickee hit it on 2026-10-28: its tenant check answered `false` for every tenant until its description was moved to 26.8.1's. The skills' tests catch the change on the skills' side (0111's RQ-03); an application already generated learns it from nothing in c4-infra.

## Proposed outcome

The README's bullet on a change of the stack's Keycloak, and each changelog entry of a version change, tell an application generated by the skills that its admin client moves with the version: move the pin, rebuild, follow the generated client's changed signatures and fields.

Success criterion: the README says it in that section, and the changelog convention asks each version change's entry to name what changes for a generated admin client (or that nothing does).

## Affected users and systems

- Developer (an application generated by the skills).
- `README.md` ("Keycloak in an application's tests"); `tests/0029-description.sh` if the convention is checked.

## Constraints

- The image, `keycloak/` and `keycloak-image.properties` are unchanged.
- The skills' 0111 keeps the check on the skills' side; this is the application's side, in words.

## Open questions

- Whether `tests/0029-description.sh` checks the new convention in each version change's entry, or the README states it only — the plan.
